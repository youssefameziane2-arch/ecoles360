1. Cadre et méthode de recette

La recette est conduite sur staging.ecoles360.com — hébergé sur le même VPS Hostinger KVM 2 que la production mais dans un projet Docker Compose distinct (-p ecoles360-staging, volumes et réseau séparés — livrable 14 v2.5 §4.3), server_name nginx dédié, base ecoles360_staging re-seedée à chaque déploiement (docker compose exec api npx prisma migrate reset --force puis docker compose run --rm api node dist/cli.js db:seed). Les comptes et données de démonstration produits par la commande de seed (livrable 10 v2.5 §3) servent de jeu d'essai reproductible. Chaque scénario est rejoué manuellement par le client et automatiquement par la suite Playwright (livrable 13 v2.5 §4). Un scénario est Conforme si toutes ses étapes passent et que les règles de gestion visées sont respectées ; sinon une réserve est ouverte (§4), qualifiée bloquante, majeure ou mineure.

3. Recette transverse (non-fonctionnel)

  • Concurrence — deux vues sponsorisées simultanées près du plafond : compteur exact, jamais dépassé (deux PrismaClient sur $queryRaw FOR UPDATE, RG12) — Conforme.
  • Numérotation des factures — séquence F2026-NNNNNN continue et sans trou sous charge parallèle (RG14) — Conforme.
  • Double proposition de fiche — deux appels concurrents à FicheProposalService.submit() : la seconde reçoit 409 proposition_deja_en_attente (RG27) — Conforme.
  • Format fr-MA — virgule décimale (4,8), espace fine des milliers (8 420), MAD suffixé, dates 24 h — Conforme.
  • Vie privée (loi 09-08) — purges du conteneur scheduler (@nestjs/schedule) : anonymisation 12 mois demandes + traces, purge journal d'audit 3 ans (RG26) — Conforme.
  • Sécurité — HTTPS (TLS 1.3) forcé, HSTS, CSP, sessions Passport en cookie HttpOnly persistées dans Redis + CSRF double-submit + Argon2id, throttling Redis (livrable 14 v2.5 §6) — Conforme.
  • Isolation des environnements — la recette s'exécute dans le projet Compose ecoles360-staging : vérifié qu'aucune écriture n'atteint les volumes ni la base de production, et que le redéploiement du seul conteneur api (up -d --no-deps api) laisse les sessions ouvertes et les files BullMQ intactes (livrable 14 v2.5 §4.1, §4.3) — Conforme.
  • Accessibilité & responsive — navigation clavier, contrastes AA, cibles ≥ 44 px, rendu mobile des back-offices — Réserve mineure (voir R-02).
