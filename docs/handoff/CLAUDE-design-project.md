# écoles360 — État du projet & consignes permanentes

**Projet réel** (pas seulement un PFE) : annuaire web payant des établissements scolaires privés au Maroc. Parents = gratuit (recherche → fiche → contact) ; établissements = clients (visibilité sponsorisée, packs de crédits, abonnement Premium). 4 surfaces : site public, espace établissement, espace secrétariat, back-office admin. Langue : français (Maroc), vouvoiement, virgule décimale (4,8), espace fine milliers, MAD après le montant.

## Stack technique (livrables 7/10/11/12/13/14 — v2.5, septembre 2026)
**NestJS 10 (API) + React 18/Vite (front) + production conteneurisée en Docker Compose sur VPS Hostinger KVM** (livrables L7–L16 en v2.5).

**Back-end** : **NestJS 10** · Node.js 20 LTS · TypeScript 5 strict, préfixe global `/api/v1` posé dans `main.ts`. Un module par domaine métier sous `api/src/modules/<domaine>/{<domaine>.module.ts, .controller.ts, .service.ts, dto/, guards/}` — 14 modules : `auth · users · etablissements · fiches · abonnements · facturation · commissions · prospects · leads · avis · contacts · articles · cms · audit` ; transverses dans `api/src/common/{guards,filters,interceptors,decorators}`. Anatomie d'une requête : Controller → `ValidationPipe` (DTO **class-validator** + class-transformer, `whitelist` + `forbidNonWhitelisted`) → Guards → Service transactionnel → interceptor de sérialisation (enveloppe `{data,meta,links}`) ; `HttpExceptionFilter` global pour `{code,message,details}` en français (409 = conflit métier, 422 = validation). **Swagger `@nestjs/swagger` → `/api/docs`**.

**Front-end** : application **séparée** `web/` — React 18 + **Vite 5**, routage par fichier **Vike** (`vite-plugin-ssr`) : **SSR ciblé du site public** (`src/pages/public/`, pour l'indexation des ~8 000 fiches — RG03/RG08, schema.org LocalBusiness) et **SPA pure** pour les back-offices (`src/pages/espace/{etablissement,secretariat,commercial}/`, `src/pages/admin/`). Client HTTP unique `src/api/client.ts` (same-origin, `credentials: include`, en-tête CSRF ; base interne `http://api:3000/api/v1` en SSR) ; **TanStack Query** pour l'état serveur et les invalidations — plus de Server Actions, une seule voie d'écriture HTTP. React Hook Form aligné sur les DTO (le 422 du ValidationPipe arbitre). Leaflet + OSM en `React.lazy`. Design system monté via `_ds_bundle.js`.

**Persistance** : **Prisma 5** sur MySQL 8 (InnoDB, utf8mb4_unicode_ci) — 23 modèles, `PrismaService` provider injectable (`OnModuleInit`/`OnModuleDestroy`), verrous `$queryRaw … FOR UPDATE` (vues RG12, factures F2026-NNNNNN RG14, propositions de fiche RG27). `prisma migrate deploy` exécuté **au démarrage du conteneur `api`**. Seeders et import open data exposés en **commandes NestJS** (`nest-commander` : `db:seed`, `import:etablissements`), exécutables en conteneur éphémère.

**Auth** : `@nestjs/passport` + `passport-local`, `express-session` + **`connect-redis`** (sessions dans Redis, donc **révocables** — RG25), cookie `HttpOnly/Secure/SameSite=Lax`, CSRF double-submit, **Argon2id**. Autorisation par **Guards** (`SessionGuard` global, `RolesGuard`, `ScopesGuard` + décorateurs `@Roles()`/`@Scopes()`) et guards de domaine — `EtablissementGuard`, `AvisModerationGuard`, `DemandeContactGuard`, `ProspectGuard`, `PropositionFicheGuard`, `LeadGuard`, `RoleGuard`, `ArticleGuard`, `AuditGuard` (les anciennes *policies* TS). Rate limiting `@nestjs/throttler` sur Redis ; en-têtes par `helmet`.

**Files & planification** : `@nestjs/bullmq` sur Redis 7 — cinq files `mail / alerts / billing / maintenance / stats` (producteurs `@InjectQueue` dans les modules, consommateurs `@Processor` dans le conteneur `worker`) ; `@nestjs/schedule` `@Cron` dans le conteneur `scheduler` (purges 02 h/04 h, backup 03 h, rappels 08 h, purge audit 3 ans). Cache : `CacheModule` Redis côté API (clés `fiche:{slug}`, `articles:public`, `faq:public`, `pages:a-propos`) + invalidation React Query côté client — **plus de `revalidateTag`**.

**Douze services métier inchangés** (devenus `@Injectable()` de leur module) : `ViewBillingService`, `FacturationService`, `SubscriptionService`, `CommissionService`, `ProspectService`, `LeadService`, `ReviewModerationService`, `ContactRequestService`, `FicheProposalService`, `ArticleWorkflowService`, `AuditService`, `CmsService`.

**Tests (L13 v2.5)** : **Jest** (défaut NestJS) + **Supertest** côté API — unitaires via `Test.createTestingModule()`, intégration HTTP sur l'application Nest complète (pipes/guards/interceptors/filtres réels, agent authentifié par `POST /auth/login`) ; **Vitest + RTL + MSW** côté composants (fixtures dérivées de l'OpenAPI `/api/docs`) ; **Playwright** cinq parcours acteur inchangés. MySQL 8 réelle en test (jamais SQLite) via `docker-compose.test.yml` ; concurrence testée avec deux `PrismaClient` sur `$queryRaw FOR UPDATE`.

**Hébergement & exploitation (L14 v2.5)** : **VPS Hostinger KVM 2** (2 vCPU / 8 Go, Ubuntu 24 LTS), domaine `ecoles360.com` chez Hostinger. **Docker Compose** en production — 7 services `api · worker · scheduler · web · mysql · redis · nginx` (les trois premiers partagent **une seule image**, trois commandes) ; volumes nommés `mysql_data`/`redis_data`/`storage` ; réseau interne, MySQL et Redis en bind `127.0.0.1`, **seul nginx publie 80/443** ; certbot **reste sur l'hôte**, certificats montés en lecture seule. Dockerfiles multi-stage → `node:20-alpine`, non-root, `HEALTHCHECK /api/v1/health`. CI GitHub Actions : `api` / `web` / **`images`** (build + push **ghcr.io** tagués par SHA, **après** les tests) / `e2e` — **le VPS ne compile jamais**. Déploiement `docker compose pull && up -d` ; rollback par tag antérieur ; **`docker compose up -d --no-deps api`** redéploie un seul composant sans toucher aux autres (les migrations doivent rester compatibles avec la version précédente). Staging = **projet Compose distinct** `-p ecoles360-staging`. PRA RPO 24 h / RTO 4 h : `docker compose exec -T mysql mysqldump` chiffré GPG → Hostinger Object Storage, rsync du volume `storage`, playbook `bootstrap.yml` réduit à Docker/Compose/certbot/ufw/fail2ban. Journaux par pilote `json-file` (10 Mo × 5). ufw 22/80/443 + fail2ban inchangés. **PM2 ne fait plus partie de la production** (politiques de redémarrage Docker + healthchecks). Loi 09-08 : purges par le conteneur `scheduler` avec entrée d'audit RG26.

> Règle à retenir : **la conteneurisation isole les runtimes ; l'indépendance fonctionnelle entre parties du site vient des modules NestJS**. Les deux mécanismes sont complémentaires.

**Stack v2.4 (obsolète, corrigée en v2.5 le 16/09/2026, conservée dans les historiques de révision des livrables)** : Next.js 14 App Router unifié (RSC + Client Components + Server Actions, Route Handlers `app/api/v1/**`), Auth.js v5, Zod + zod-i18n-map, policies TS, node-cron, Vitest serveur, Nginx + Node 20 + **PM2** + releases atomiques par symlink.
